# 外部顾问意见：自由布局编辑的产品设计方案

> 2026-08-10 ｜ 视角：面向中文创作者市场的产品与设计顾问
> 依据：[brief-free-layout.md](brief-free-layout.md)、[design/design-direction.md](design/design-direction.md)（八条法则+反面清单）、[design/grid-spec.md](design/grid-spec.md)、[design/template-system.md](design/template-system.md)、[advice-kimi.md](advice-kimi.md)
> 立场声明：先说结论——**这个需求的真实诉求不是「自由」，是「我的主页看起来不像套模板的」。自由拖拽是用户给出的解决方案，不是问题本身。** 下面按四个问题展开，最后给一条反直觉建议。

---

## 一、用户到底想要什么

### 1. 把「自由编辑大小和位置」翻译成真实诉求

「每个框都可以自由编辑大小和位置」这句话里藏着三个完全不同的诉求，混淆它们会导致做错产品：

| 表层诉求 | 真实诉求 | 证据 |
|---|---|---|
| 调整大小 | **强调主次**：让最重要的链接（作品集/店铺）视觉最大 | 现有 LG 档已在解决，但只有一档不够细腻 |
| 调整位置 | **掌控节奏**：页面从上到下的阅读顺序由我定，不是我加块的顺序 | dnd-kit 排序已解决大半 |
| 「更大的自由设计空间」 | **去模板感**：不想和用同一模板的人撞脸，想要 Bento 那种「杂志感」「设计过的感觉」 | design-direction §1 把「不对称构图、打破模板感」列为高级感的来源之一——用户要的是这个情绪，不是坐标轴 |

结论：**用户要的是「排版的结果好看且与众不同」，拖拽只是他唯一能想到的实现路径。** 这对形态选择是决定性的——见第二节。

### 2. 拆成具体场景

| # | 用户 | 时刻 | 想达成什么 | 现有能力是否够 |
|---|---|---|---|---|
| S1 | 插画师（P1） | 建页后第 2 分钟，对着模板成品页 | 「作品集」要最大最显眼，约稿须知小一点 | LG/MD/SM 基本够，但「最大」只有跨 2 列一档 |
| S2 | 小店主（P1） | 上新时 | 把本周主推商品卡挪到最上面，加粗加大 | 排序够，强调手段单一 |
| S3 | 博主（P1） | 看到别人的 Bento 风页面后 | 「我也要那种错落的杂志感」——这是**审美诉求**，不是功能诉求 | 不够，这是本需求的核心驱动 |
| S4 | 播客主（P0/P1） | 发朋友圈前 | 希望页面截图好看，值得被晒 | 取决于成品质量，不取决于自由度 |
| S5 | 出海创作者（P0） | 对比 Linktree/Bento 替代品时 | 把「可定制程度」当选型 checklist 的一项 | ** checklist 诉求≠使用诉求**，90% 的人勾完就不用 |

注意 S3 和 S5：一个是情绪、一个是 checklist，它们声音最大，但都不需要「自由画布」来满足。

### 3. 竞品参照：三种自由度，三种代价

| 竞品 | 给了多少自由 | 代价 | 对我们的启示 |
|---|---|---|---|
| **Bento** | 2 列（移动端）/4 列（桌面）网格内拖 span，磁贴吸附，**不允许自由 x/y** | 网格会产生「洞」（1 列空隙），靠 auto-flow dense 和一键整理兜底；编辑态在手机上依然局促，最终产品关停 | **自由度的上限 = 网格 span，不是画布**。它的磁贴编辑已被验证是「好看」与「自由」的最优折中——用户怀念的正是它 |
| **Notion** | 块纵向拖拽 + 拖到侧缘分栏（隐式 2-4 列） | 分栏是隐式状态，用户经常「不知道怎么就变成两栏了 / 怎么变回去」；手机上分栏全部塌回单列，桌面排的版在手机上不存在 | 隐式布局状态的认知成本极高；**双端布局分叉是灾难**——这条直接否决「桌面自由排、移动端降级」的方案 |
| **Canva** | 绝对定位画布，x/y/w/h/旋转/层叠全给 | 默认产出丑（空画布恐惧症 + 无设计纪律）；移动端几乎无法编辑；成品在他人手机上可能错位 | 反面对照组：自由度给满 = 把设计责任全部推给用户。我们的用户（中文创作者、手机为主）**没有能力也没有意愿承担这个责任** |

**裁决：Bento 形态（受约束网格 + span 拖拽）最适合我们的人群。** 理由三条：

1. 我们的用户 80% 在手机上**消费**自己的页面（微信内），但**编辑**主要也发生在手机上——Canva 式画布在 375px 上根本不可操作；
2. Bento 关停留下的情绪真空正是我们即刻发帖的钩子（见 advice-kimi §1），做「Bento 能做的排版」比做「Bento 做不到的自由」更能接住这批难民；
3. 我们的护城河是「默认即好看」，网格约束是这条护城河的城墙——画布形态等于拆墙。

## 二、形态建议与交互设计

### 1. 形态裁决：(b) 的收窄版——「跨度网格」，列数不变

不做 4 列、不做绝对定位。在**现有 2 列栅格**上把尺寸从三档枚举（SM/MD/LG）扩展为**跨度模型**：

```
Block.span = { col: 1|2, row: 1|2|3 }   // 共 6 种跨度组合
```

- 旧数据自动映射：SM→{1,1}，MD→{1,2}，LG→{2,2}，零迁移成本；
- 新增能力只有两档：**{2,1} 横幅块**（通栏薄条，放公告/一句 slogan，这是目前表达不了的形态）和 **{1,3}/{2,3} 高块**（竖图、歌单、长文案）；
- `grid-auto-flow: dense` 保持不变，洞由引擎自动填补，用户不需要理解。

这就是「Bento 编辑器」的诚实版本：用户感知到「大小和位置都能调」，系统层面只是 span 白名单从 3 种变 6 种。

### 2. 桌面端编辑器交互流程（480px 画布，所见即所得）

**调整大小：**

1. 鼠标悬停区块 → 卡片右缘和下缘浮现两个**跨度手柄**（accent 色小圆片，右缘管列、下缘管行）；
2. 拖动下缘手柄 → 卡片高度在 1/2/3 行之间**跳变吸附**（不是连续缩放），每次吸附有 80ms 弹性动画 + 轻微触感音（编辑器内，非公开页）；
3. 拖动右缘手柄 → 1 列 ↔ 跨 2 列切换；
4. 拖动全程显示**幽灵占位框**（accent 12% 淡底 + 虚线描边）预告落点，其余卡片实时流动让位——用户拖的是「结果」，不是「坐标」。

**调整位置：**

1. 按住卡片任意处拖拽（保留现有 dnd-kit），卡片浮起（阴影加深一档，海拔语言与 design-direction §3 一致）；
2. 目标位置显示幽灵占位框，松手落位；
3. 不允许悬空、不允许重叠——松手位置永远吸附到最近的合法网格槽。

**即时反馈兜底：** 每次操作后预览区右上角短暂出现「↺ 撤销」toast（2 秒），降低试错心理成本。

### 3. 移动端编辑器：窄屏上「自由定位」是不是伪需求？

**是伪需求，但要小心区分「编辑」和「呈现」。**

- **呈现端**：公开页在任何设备上都是同一个 2 列网格（桌面限宽 480px），不存在窄屏降级问题——这是现有架构的巨大优势，必须死守；
- **编辑端**：375px 屏上双指拖 span 手柄，手指会挡住整张 165px 宽的卡片，落点不可见，误触率极高。Bento 自己的移动端也没做好这件事。

**替代方案：移动端不做「拖拽排版」，做「点选排版」。**

1. **排序**：沿用长按拖拽纵向排序（成熟手势，保留）；
2. **改尺寸**：选中卡片 → 底部弹起**跨度选择器**，6 种跨度画成 6 个迷你网格示意图（两行高的小缩略图，所见即所得地展示「横幅/标准/高块」），点一下即生效——比拖拽快、比拖拽准；
3. **一键整理**（移动端排版的第一公民，见第三节）；
4. **「换个排法」骰子**：见第五节反直觉建议。

原则一句话：**桌面端拖的是卡片，移动端点的是结果。** 两端产出同一份 span 数据，公开页渲染完全一致——绝不出现 Notion 式的双端布局分叉。

## 三、护栏设计：给自由度，同时守住「默认即好看」

### 1. 给哪些自由度（白名单）

| 自由度 | 形式 | 理由 |
|---|---|---|
| 块顺序 | 拖拽 | 已有 |
| 块跨度 | 6 种 span 白名单内拖拽/点选 | 本需求核心 |
| 块显隐 | 已有 isVisible | 已有 |
| 每页 LG（跨 2 列）数量 | 软上限 3 个，超出时编辑器黄条提示「主角太多等于没有主角」 | grid-spec §2 的「LG ≤ 2」纪律，放宽一档但保留警告 |

### 2. 坚决不给的自由度（黑名单）

| 黑名单项 | 为什么坚决不给 |
|---|---|
| ❌ 绝对定位 x/y（自由画布） | 摧毁「默认即好看」，移动端不可编辑，双端必分叉——三大红线全踩 |
| ❌ 像素级连续宽高 | 产生对齐灾难（差 3px 的两张卡并排是「廉价感」的第一来源）；吸附到行高基准是唯一正确答案 |
| ❌ 列数自定义（3 列/4 列） | 165px 再切一半剩 80px，文字全部挤爆；且破坏桌面/移动同构 |
| ❌ 旋转、层叠、z-index | 直接打开反面清单里的「花哨」闸门 |
| ❌ 块间重叠/出血 | 首卡头像出血是**官方模板特权**（法则 §4），开放给用户等于人人可做坏掉的杂志版式 |
| ❌ 桌面/移动分别保存两套布局 | Notion 已验证是认知灾难；我们的 480px 限宽架构根本不需要它 |
| ❌ 每块自定义背景色/圆角 | 这是主题 token 的领地（法则 §1 单色纪律），越界即「八套主题八种花哨」的块级版本 |

### 3. 主动护栏机制（按实现成本排序）

1. **吸附即全部**：所有尺寸变化只在 6 种合法 span 间跳变。这一条做完了，80% 的丑就已经不可能发生。
2. **空洞自动填补**：`dense` flow 现有能力，span 放开后必须验证{1,1}小块能自动回填{1,2}高块旁的空隙——编辑器预览与公开页用同一渲染器，所见即所得保证这一点。
3. **一键整理（Tidy）**：编辑器工具栏常驻「✨ 整理」按钮，执行三件事：按内容类型重排建议顺序（hero 链接靠前、社交贴纸靠后）→ 消除孤洞 → LG 超限时自动降级最小的那个。整理前快照，可一键撤销。这是移动端排版的主交互，也是「我把页面排乱了怎么办」的终极退路。
4. **丑陋检测（越界提示，不阻断）**：保存时跑三条启发式规则，命中则在编辑器顶部出**可忽略的黄条**（绝不弹窗打断）：
   - 连续 2 个以上跨 2 列大块相邻 →「大卡片连着放会显得拥挤，中间穿插小卡片更有呼吸感」；
   - 页面总高 > 3 屏且前 1 屏内无 LG 块 →「第一屏没有重点，访客可能不知道先看哪」；
   - 出现无法被填补的单列孤洞且页面末行半空 →「底部有个空缺，点这里一键整理」。
   检测规则必须是**建议**而非**错误**——用户有权留着洞，那是他的杂志留白。
5. **模板起步不变**：onboarding 依旧从 8 个场景模板进，自由布局是「在好看默认值上微调」，不是「从空白开始创作」。这条流程不动，自由度就永远有安全网。

## 四、对模板体系与主题体系的影响

### 1. 8 个场景模板：不用重做，做增量映射

- 模板 schema 的 `size` 字段改为 `span: {col, row}`，旧值 SM/MD/LG 按固定映射转换（SM→{1,1}、MD→{1,2}、LG→{2,2}），**存量模板 JSON 一次脚本迁移，渲染结果逐像素不变**——这是兼容性的验收标准；
- 迁移后做一轮「模板 2.0 润色」（不是重做）：给其中 3 个模板各加 1 个 {2,1} 横幅块（如播客模板的「🎙 新一集已更新」公告条），让新能力在老模板里露出——这比新做模板便宜，还能制造一次「模板焕新」的上新话题；
- 模板的留白节奏（LG ≤ 2、SM 成对）继续保持，它是「默认即好看」的结构性来源。

### 2. 主题体系：零改动，且必须保持零改动

- 主题 token（`neutral / accent / elevation / typography / texture`）管「颜色与质感」，span 管「几何」，两者正交。自由布局不引入任何新视觉 token，也不允许任何块级覆写——法则 §1 的单色纪律和 §3 的两层海拔在任意 span 组合下都必须成立；
- 唯一需要回归测试的交叉点：**行高 3 档（252px+）高块内的内容排版**——IMAGE 高块 `object-fit: cover` 无风险，TEXT 高块需定义垂直居中还是顶对齐（建议顶对齐 + 内容上限截断，避免高块里一行字悬空的丑态）。在 grid-spec 补一行即可；
- 社区主题投稿管道（template-system §4）完全不受影响，CI 校验项不变。

## 五、反直觉建议

**砍掉一半的「编辑自由度」预算，拿去做一个「🎲 换个排法」按钮。**

行业直觉是「用户要自由，就给更顺手的拖拽」。我的判断相反：**对照 S3 场景的诉求（「不想和别人撞脸」），随机比拖拽更对症。**

机制：点击骰子 → 系统在当前区块集合的**合法布局空间**内（满足全部护栏规则、LG ≤ 2、无孤洞、内容类型约束）随机生成一个新排版，带 200ms 洗牌动画；不满意再点，或一键回到整理态。每点一次，用户都得到一个在网格规范内、但和模板不一样的「杂志感」版面。

为什么这比拖拽编辑器值钱：

1. 拖拽是「用户自己当设计师」，骰子是「设计师陪用户抽卡」——前者给用户责任，后者给用户惊喜。我们的用户没有设计能力，抽卡永远比徒手排好看；
2. 实现成本不到拖拽编辑器的三分之一（纯数据层排列 + 约束求解，无手势、无碰撞检测、无手柄 UI），且天然免疫「用户排出丑版式」；
3. 它是天然的传播素材：「一键换排版，抽到你的专属版面」比「我们支持拖拽编辑」更像一条小红书/即刻帖子。

自由拖拽仍然要做（它是 checklist 项，S5 人群和海外评测会看），但产品叙事的主角应该是骰子——**「自由」卖给评测者，「好看且不撞脸」卖给用户。**

---

## 总结（三行）

1. 用户要的不是坐标自由而是「好看且不撞脸」：形态选 Bento 式收窄版——2 列栅格不变，尺寸从 3 档扩为 6 种 span 白名单，绝对定位画布永久进黑名单。
2. 桌面端拖卡片、移动端点结果（跨度选择器 + 一键整理），两端共用同一份 span 数据同一渲染器；护栏靠「吸附即全部 + 一键整理兜底 + 可忽略的丑陋提示」，绝不做阻断式校验。
3. 模板只迁移不重做、主题 token 零改动；把省下的编辑自由度预算押注在「🎲 换个排法」上——随机合规排版比拖拽编辑器更便宜、更好看、也更值得发帖。

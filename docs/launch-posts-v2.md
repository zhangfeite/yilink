## 1. V2EX「分享创造」帖

**标题**：

> [开源] 一链 YiLink：可 Docker 自部署的中文 link-in-bio 聚合主页，自由布局编辑器 + 微信内打开适配（邀请制公测，帖内发码）

**正文**：

把散落在各平台的自己装进一个页面：GitHub、掘金、公众号、B 站、小红书一次聚合，一个链接 + 一张二维码 + 一张分享海报发出去。起因很简单——国内同类工具要么停服要么丑，海外的在国内访问不稳，而「微信里能正常打开」「二维码/海报一等公民」这两件事没有任何开源项目做过，所以自己写了一个。编辑器做的是自由布局而不是固定槽位：每个区块的位置和大小都可以直接拖，这也是它和多数同类工具最大的不同。

- 在线体验：https://yilink.app （演示主页：https://yilink.app/p/demo-photographer ）
- 仓库：https://github.com/zhangfeite/yilink （Apache-2.0，三张真机截图在 README 顶部）

**现在是什么状态**

邀请制公测。注册需要邀请码，领取方式见文末。

**能力清单（都已上线，可现场验证）**

- **自由布局编辑器（BENTO）**：区块拖拽改位置和大小，移动端点选换位，排乱了一键整理回整齐版式；8 个模板都有对应的自由布局版，公开页零 JS 渲染。不喜欢自由排的，还有列表、网格两种固定布局，共三种布局；
- 8 个场景模板 × 8 套主题，5 分钟出页；
- 微信内打开适配：转发分享卡片、iPhone 安全区、防安卓强制反色（旧内核有兜底）；
- 二维码下载 + 浏览器端生成主题化分享海报，不经过服务器；
- 统计：PV/UV/链接点击，可按区块、按来源渠道拆分，30 天日趋势报表；访问按访客哈希去重（每页每小时），原始事件 30 天后清理；
- 内容审核：真实违禁词库 + URL 域名黑名单 + 发布状态机——命中违禁直接拒绝发布，命中观察词进人工审核队列（页面不公开），已发布页面的每次修改都会重新过审；
- 数据一键导出 JSON，随时打包走人；
- Docker 一键自部署（SQLite，单容器）；海外托管官方路径是 Cloudflare Workers + D1，迁移零改造。

**定价**

免费版 3 个页面，够用不收钱；买断 $12 十页 / $25 五十页，一次付费终身使用，**永不涨价，老用户永远保价**。说实话的部分：收款方 LemonSqueezy 我还没完成开户，所以**购买入口现在显示「即将开放」**，价格先挂出来是因为我觉得第一天明码标价，比日后「养肥再收」诚实。

**邀请码怎么领**

- 回复本帖即可，我私信发码（回复里不用说邮箱，私信就行）。码是我手工发的，发完手头的批次会按审核和限频的承压情况再补，所以不承诺数量和时限；
- 不想等的，去 GitHub 仓库开 issue，标题带「邀请码」三个字，同样发；
- 说句实话：邀请码目前是白名单制，没有逐次核销，它挡的是脚本和批量注册，挡不住铁了心要进来的人。邀请制真正的目的，是让审核和限频在真实流量下跑稳之前，规模别失控——我不想拿第一批用户的主页去验证。

**未完成项（说在前面，免得浪费你的点击）**

1. **LemonSqueezy 未开户**：买断套餐的收款链路没通电，代码和 webhook 都就绪，差我这边开户，所以购买入口显示「即将开放」；
2. **国内访问链路未验证**：yilink.app 域名不可备案（已核实），国内访问走的是 Cloudflare 默认链路，速度和稳定性我没有承诺的底气；可备案域名和备案流程都还没启动。介意这点的建议 Docker 自部署；
3. **微信转发卡片目前只有 og 标签层**：公开页的 og:title/description/image 已配齐，转发出去有正常的卡片；JS-SDK 增强层（微信内自定义分享标题/缩略图）需要公众号 AppID，生产环境还没配，所以目前是 og 兜底形态，不是满血形态；
4. **自定义域名、活码没做**：都在 roadmap 里；模板目前 8 个。

求 star，更求拍砖。技术细节（微信适配那部分）我会另写一篇长文发掘金，这里不展开。

## 附：改了什么、为什么

对照 `launch-fact-check.md` 逐条说明：

1. **自由布局从「没做」改为核心卖点并前置**（清单 #5）。原稿把 BENTO 自由布局写进「roadmap 里没做」，但它已完整上线：拖拽改大小和位置、移动端点选、一键整理、8 个模板都有自由布局版、公开页零 JS 渲染。这是产品最大的差异化，v2 把它放进标题、开场白和能力清单第一条。V2EX 能力清单、即刻短帖第三段同步改写。
2. **布局从双布局改为三种**（清单 #6）：列表 / 网格 / 自由布局，V2EX 能力清单第一条和即刻短帖均已更正。
3. **统计维度按实际上调**（清单 #7）：由「访问/点击两个维度加 30 天报表」改为 PV/UV/点击 + 按区块 + 按来源渠道 + 30 天日趋势，并补了去重和原始事件清理两个可验证细节。
4. **邀请码段落重写**（清单 #3、#4）：删掉「前 50 位」（与实际码数对不上），改为「不承诺数量和时限」；同时删掉自相矛盾的「安全考虑」表述，如实说明邀请码是白名单制、无逐次核销，邀请制的真实目的是控制规模让审核链路先跑稳。
5. **补微信分享卡片披露**（清单 #8）：V2EX 未完成项新增第 3 条——转发卡片目前是 og 标签层生效，JS-SDK 增强层因未配公众号 AppID 还没通电，避免读者把「转发分享卡片」理解成满血形态。
6. **合规红线保持**：未出现 Linktree 商标对比、未编造用户数/star 数、购买入口两处均写「即将开放」。

**遗留提醒（不属于本次文案改写范围，但发帖前要知道）**：清单 #1、#2 两条 ❌ 在代码里仍未解决——我核对过，`apps/web/src/app/studio/data/page.tsx` 目前仍只渲染「统计面板将在后续版本开放」占位文案，`/api/v1/me/export` 在 studio 里也没有入口按钮。也就是说 v2 文案里的「统计报表」和「一键导出」两条承诺，发帖前要么按清单建议接上 UI（后端已完备，成本低），要么从文案里删掉，否则仍是过度承诺。

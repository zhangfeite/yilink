# 需求简报：自由布局编辑（区块大小与位置可自由调整）

> 2026-08-10 ｜ 产品负责人提出 ｜ 供 Codex / Kimi 会诊，Claude 裁决

## 原始需求

「个人界面还需要有几个功能，每个框都可以自由编辑大小和位置，给用户更多更大的自由设计空间。」

## 现状（会诊前必须理解的约束）

1. **数据模型**：`Block(type, position:Int, size:'SM'|'MD'|'LG', isVisible, config JSON)`；渲染 `layout:'LIST'|'GRID'`。GRID 是**固定 2 列**、`grid-auto-flow: dense`，SM=1×1 / MD=1×2 / LG=跨 2 列（见 docs/design/grid-spec.md）。
2. **编辑器**：dnd-kit 纵向拖拽排序 + 尺寸三选一；右侧 375px 实时预览复用公开页渲染器（所见即所得，同一套组件）。
3. **设计法则**（docs/design/design-direction.md，八条 + 反面清单）：产品的视觉护城河是「默认即好看」；反面清单明确禁止「八套主题八种花哨」式的失控。用户曾以「很丑，没有任何高级感」否决过 v1 设计——自由度不能以牺牲成品质量为代价。
4. **首要场景是移动端**：公开页 375px 基准、桌面限宽 480px（保持手机版式）。**自由拖拽定位在窄屏上的可用性与可编辑性是核心难题。**
5. **PRD 已排期**：V1.x 列有「自由拖拽网格编辑器」，本需求是把它提前并扩大。
6. 渲染与编辑共用组件；公开页要求零框架 JS（SSR 直出 + ≤5KB 内联脚本），任何新布局能力不能破坏这条性能预算。
7. 现有 8 个场景模板、8 套主题均基于当前 LIST/GRID 语义，改动需给出迁移方案（不能让存量页面变形）。

## 需要会诊回答的问题

1. **形态**：应该做成哪一种？(a) 增强网格（更多尺寸档/列数，仍受栅格约束）；(b) 真正的自由网格（拖拽调整 col/row span，类 Bento 编辑器）；(c) 自由画布（绝对定位 x/y/w/h）；(d) 其他组合。
2. **移动端**：窄屏上如何编辑与呈现？桌面自由布局与移动端的关系（响应式降级？双套布局？）
3. **数据模型**：如何扩展且兼容存量数据与模板？
4. **质量护栏**：如何在给自由度的同时守住「默认即好看」（吸附、约束、模板起步、越界检测…）？
5. **范围**：MVP 应该做多小才能验证价值？什么必须后置？
